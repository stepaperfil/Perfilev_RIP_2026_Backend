# Л/р 1 — дизайн и базовая шаблонизация

⬅ [Общее описание проекта и список веток](../../tree/main)

## Что реализовано в этом спринте

- Доменная модель этапа жизненного цикла актива (услуги): `Title`, `Description`, `ImageKey`, `VideoKey`, `Status` (`draft`/`published`), `Likes`, `PricePerUnit`, `StagePosition`. Данные пока захардкожены в репозитории (без БД — это будет в следующих лабах).
- Три экрана на сервер-сайд шаблонизации (`html/template` + Gin):
  - **Плитка** — каталог опубликованных этапов, фильтр по цене за единицу.
  - **Лента** — детальная карточка этапа (фото/видео, лайк, переход к следующему по порядку).
  - **Добавление** — черновик этапа со статусом `draft`.
- Хранение изображений/видео этапов через **MinIO** (URL собирается по ключу объекта).
- Вёрстка и цветовая схема в стиле Limble CMMS.

## Роуты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/stages` | Список опубликованных этапов; `?maxPrice=` — фильтр по цене за единицу |
| GET | `/stages/:id` | Детальная карточка этапа; `?next=true` — следующий по порядку этап |
| GET | `/stages/draft` | Текущий черновик этапа (статус `draft`) |

## Технологии

- **Go** + **Gin** — роутинг
- **html/template** — серверная шаблонизация
- **MinIO** — хранение медиа этапов

## Запуск

```powershell
docker compose up -d   # MinIO
go run ./cmd/tcoApp
```

Приложение поднимется на `http://localhost:8080/stages`.

## Что не входит в эту лабу

Работа с БД (PostgreSQL), роли пользователь/модератор, сущность «заявка», изменяющие эндпоинты (создание/модерация) — планируются в следующих спринтах.
